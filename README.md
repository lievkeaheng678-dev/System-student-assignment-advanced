# Student Portal (Django + PostgreSQL, ready for Render)

Student registration and sign-in, built to deploy to Render.com with a managed Postgres database in one click.

## What it does

**Accounts**
- Register with name, email, program, year and a strength-checked password
- A student ID (`STU-2026-48213`) is issued on registration
- Sign in with **email or student ID**, case-insensitive
- "Keep me signed in" (30 days) or end the session when the browser closes
- Forgot-password flow with one-hour reset links
- Email confirmation links (optional enforcement)

**Security**
- Lockout after 5 wrong passwords in 15 minutes, per account name and per IP, with the same answer for names that don't exist
- Sign-in history page (device, time, address, success or failure)
- "Sign out other devices"
- Honeypot field against sign-up bots
- Salted PBKDF2 password hashing (Django default), CSRF on every form, POST-only sign-out
- HTTPS redirect, secure cookies and HSTS in production
- Delete-your-own-account with password confirmation

**Dashboard**
- Student ID card, profile-progress checklist, recent sign-ins
- The register page shows your card filling in live as you type

**Admin** at `/admin/`: search by name, email or student ID; filter by program, year, verified; read-only sign-in log.

## Run it on your computer (Windows)

```powershell
cd student_portal
python -m venv .venv
.venv\Scripts\activate
pip install -r requirements.txt
copy .env.example .env
python manage.py migrate
python manage.py seed_demo
python manage.py runserver
```

Open http://127.0.0.1:8000. Locally it uses a SQLite file, so you don't need Postgres.
Emails (confirmation, password reset) print in the terminal window.

Make yourself an admin:

```powershell
python manage.py createsuperuser
```

Run the tests:

```powershell
python manage.py test
```

> If `pip install` fails on `psycopg` with Python 3.14, use Python 3.12 or 3.13 for this project
> (Render is pinned to 3.12 by `.python-version`).

## Put it live on Render

1. **Push the folder to GitHub.** Create an empty repository, then from inside `student_portal`:
   ```powershell
   git init
   git add .
   git commit -m "Student portal"
   git branch -M main
   git remote add origin https://github.com/YOUR-NAME/student-portal.git
   git push -u origin main
   ```
   `render.yaml` must sit at the top level of the repository, which it does.

2. **Create the Blueprint.** In the Render dashboard click **New, then Blueprint**, connect GitHub, and choose the repository.

3. **Fill in one value.** Render lists the settings from `render.yaml` and asks for `DJANGO_SUPERUSER_EMAIL`. Enter the email you want for the admin login.

4. **Click Apply.** Render creates the Postgres database and the web service, then runs the build:
   installs packages, collects static files, applies migrations, creates your admin and the demo student.

5. **Open your site** at the `https://student-portal-XXXX.onrender.com` address shown on the service page.

6. **Admin password:** open the web service, then **Environment**, and reveal `DJANGO_SUPERUSER_PASSWORD`. Sign in at `/admin/` with your email and that password.

### What the Blueprint sets up

| Piece | Setting |
|---|---|
| Web service | Python, free plan, `gunicorn config.wsgi:application` |
| Database | free PostgreSQL, connected automatically through `DATABASE_URL` |
| Build | `pip install -r requirements.txt && python manage.py render_setup` |
| Health check | `/healthz/` (answered before the database, so a slow DB can't fail a deploy) |
| Python | 3.12 via `.python-version` |
| Secrets | `SECRET_KEY` and the admin password are generated by Render |

### Free-plan limits you should know about

These come from Render's own free-tier documentation (checked while building this):

- **The free database expires 30 days after it's created.** After that there is a 14-day grace period to upgrade it; then Render deletes it and its data. Free databases also have no backups, and each Render account can have only one.
- **The free web service sleeps** after about 15 minutes with no traffic. The first visit afterwards takes up to a minute to wake it.
- 750 free instance hours a month are shared across your workspace.

So this is a good demo setup. For anything students really depend on, upgrade the database to a paid instance first.

### Emails on the demo

With no mail server configured, confirmation and reset emails are **printed to the Render logs**. Open the service, then **Logs**, and look for the link. To send real email, add these under **Environment** (a Gmail app password, Brevo, Mailgun and so on all work):

```
EMAIL_HOST=smtp.gmail.com
EMAIL_PORT=587
EMAIL_HOST_USER=you@gmail.com
EMAIL_HOST_PASSWORD=your-app-password
DEFAULT_FROM_EMAIL=Student Portal <you@gmail.com>
```

Then, if you want to force people to confirm their email before they can sign in, also set `REQUIRE_EMAIL_VERIFICATION=true`. Leave it off until email actually works, or nobody will be able to log in.

## Settings (environment variables)

| Variable | Default | What it does |
|---|---|---|
| `SECRET_KEY` | none, required | Signs sessions and links. Render generates it. |
| `DEBUG` | `false` | Keep false online. |
| `DATABASE_URL` | SQLite file | Postgres connection. Render fills it in. |
| `SITE_NAME` | Student Portal | Shown in the header, ID card and emails. |
| `DEMO_MODE` | `false` (`true` in the blueprint) | Shows the demo banner and demo login; locks the demo account's password and deletion. |
| `SEED_DEMO` | `false` (`true` in the blueprint) | Recreates the demo student on each deploy. |
| `DJANGO_SUPERUSER_EMAIL` / `_PASSWORD` | none | Creates an admin on first deploy if none exists. |
| `REQUIRE_EMAIL_VERIFICATION` | `false` | Block sign-in until the email link is clicked. |
| `LOGIN_MAX_ATTEMPTS` / `LOGIN_LOCKOUT_MINUTES` | `5` / `15` | Lockout rule. |
| `ALLOWED_HOSTS`, `CSRF_TRUSTED_ORIGINS` | the Render hostname | Add your custom domain here, comma separated. |
| `SECURE_HSTS_SECONDS` | `3600` | Raise to a year once you're sure HTTPS works everywhere. |
| `EMAIL_*`, `DEFAULT_FROM_EMAIL` | console output | Real email, see above. |

## Before real students use it

1. Set `DEMO_MODE=false` and `SEED_DEMO=false`.
2. Upgrade the database from the free plan, or you'll lose it at day 30.
3. Configure real email.
4. Replace the placeholder terms of use. The sign-up checkbox links to nothing yet.
5. Profile photos aren't included on purpose: Render's disk is wiped on every deploy. Add object storage (S3, Cloudinary) first if you want uploads.

```
templates/         pages, partials (form field, ID card), emails

```
